# ⏱ Big-O нотация и сложность алгоритмов

---

## 🔹 Что такое Big-O

> [!note] Определение
> **Big-O** — математическая нотация для описания верхней границы роста времени выполнения или потребления памяти алгоритма в зависимости от размера входных данных `n`.

Мы оцениваем **наихудший случай** (worst case), отбрасывая константы и слагаемые меньшего порядка.

```
T(n) = 3n² + 5n + 100  →  O(n²)
```

---

## 🔹 Иерархия сложностей (от лучшей к худшей)

| Нотация | Название | Пример |
|---------|----------|--------|
| O(1) | Константная | Доступ к элементу массива по индексу |
| O(log n) | Логарифмическая | Бинарный поиск |
| O(n) | Линейная | Линейный поиск |
| O(n log n) | Линейно-логарифмическая | Merge Sort, Quick Sort (avg) |
| O(n²) | Квадратичная | Bubble Sort, вложенные циклы |
| O(n³) | Кубическая | Умножение матриц (наивное) |
| O(2ⁿ) | Экспоненциальная | Перебор всех подмножеств |
| O(n!) | Факториальная | Перебор всех перестановок |

## 🔹 Временная сложность (Time Complexity)

Показывает, **как растёт время** выполнения при увеличении `n`.

### O(1) — константная
```java
int getFirst(int[] arr) {
    return arr[0]; // всегда одна операция
}
```

### O(n) — линейная
```java
int findMax(int[] arr) {
    int max = arr[0];
    for (int x : arr) {   // n итераций
        if (x > max) max = x;
    }
    return max;
}
```

### O(n²) — квадратичная
```java
void printPairs(int[] arr) {
    for (int i = 0; i < arr.length; i++) {        // n
        for (int j = 0; j < arr.length; j++) {    // n
            System.out.println(arr[i] + " " + arr[j]);
        }
    }
}
```

### O(log n) — логарифмическая
```java
// Каждый шаг делит задачу пополам
int binarySearch(int[] arr, int target) {
    int lo = 0, hi = arr.length - 1;
    while (lo <= hi) {
        int mid = (lo + hi) / 2;
        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
```

## 🔹 Пространственная сложность (Space Complexity)

Показывает, **сколько дополнительной памяти** потребляет алгоритм.

| Пример | Space |
|--------|-------|
| Изменение массива на месте | O(1) |
| Создание копии массива | O(n) |
| Матрица n×n | O(n²) |
| Рекурсия глубиной n | O(n) — стек вызовов |

> [!warning] Рекурсия и память
> Каждый рекурсивный вызов занимает место в стеке вызовов. Рекурсия глубиной n = O(n) по памяти даже без явного выделения памяти.

## 🔹 Три случая оценки

| Случай | Описание | Нотация |
|--------|----------|---------|
| Best case | Лучший сценарий | Ω (Omega) |
| Average case | Средний сценарий | Θ (Theta) |
| Worst case | Худший сценарий | O (Big-O) |

> [!tip] На практике
> В большинстве задач и собеседований оценивают **worst case** через Big-O.

---

## 🔹 Правила упрощения

```
1. Отбрасываем константы:   O(3n) → O(n)
2. Отбрасываем младшие члены: O(n² + n) → O(n²)
3. Разные входы — разные переменные: два цикла по a и b → O(a + b), не O(n)
4. Вложенные циклы — перемножаем: цикл в цикле → O(a * b)
```

## 🔹 Итог

> [!tip] Шпаргалка
> - **O(1)** — идеально, не зависит от данных
> - **O(log n)** — отлично, бинарный поиск / деревья
> - **O(n)** — приемлемо, один проход по данным
> - **O(n log n)** — хорошие сортировки
> - **O(n²)** — допустимо только при малых n
> - **O(2ⁿ), O(n!)** — только при n ≤ 20-25
