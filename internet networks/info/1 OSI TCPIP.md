> [!abstract] Зачем это нужно?
> Модели OSI и TCP/IP — это **универсальный язык** для описания того, как работают сети. Без них невозможно понять ни один другой протокол.

## Модель OSI — 7 уровней

> [!info] Что такое OSI?
> **OSI (Open Systems Interconnection)** — это теоретическая модель, которая описывает передачу данных как **7 отдельных шагов**. Каждый уровень отвечает за свою задачу и не знает о деталях соседних уровней.

```
┌─────────────────────────────────────────────────────────────┐
│  №  │    Уровень       │  Данные   │    Протоколы/Устройства │
├─────┼──────────────────┼───────────┼─────────────────────────┤
│  7  │ 🖥️ Прикладной    │  Данные   │  HTTP, DNS, DHCP, FTP   │
│  6  │ 🔄 Представления │  Данные   │  SSL/TLS, JPEG, ASCII   │
│  5  │ 🤝 Сеансовый     │  Данные   │  NetBIOS, RPC           │
│  4  │ 🚚 Транспортный  │  Сегмент  │  TCP, UDP               │
│  3  │ 🗺️ Сетевой       │  Пакет    │  IP, ICMP, Роутер       │
│  2  │ 🔌 Канальный     │  Кадр     │  Ethernet, Switch, MAC  │
│  1  │ ⚡ Физический     │  Биты     │  Кабели, Хаб, Wi-Fi     │
└─────────────────────────────────────────────────────────────┘
                Отправитель                     Получатель
                УПАКОВКА ↓                      РАСПАКОВКА ↑
```

### Уровень 1 — Физический ⚡

> [!note] Физический уровень
> **Передача физических сигналов** — токов, света или радиоволн. Здесь нет адресов, только биты.

| Параметр | Значение |
|----------|----------|
| Единица данных | Биты (0 и 1) |
| Устройства | Хаб, репитер |
| Технологии | Ethernet, Wi-Fi, Bluetooth, ИК-порт |
| Среды передачи | Медный кабель, оптоволокно, радиоэфир |

**Типы кабелей:**
- **Коаксиальный** — старый, до 10 Мбит/с. Сейчас используется для антенн ТВ
- **Витая пара** — 8 медных проводов, попарно скрученных. Полудуплекс (2 пары) / дуплекс (4 пары)
- **Оптоволокно** — стеклянное волокно, передаёт свет. Максимальная скорость

---

### Уровень 2 — Канальный 🔌

> [!note] Канальный уровень
> Превращает физический сигнал в **кадры (frames)**, добавляет MAC-адреса, проверяет ошибки передачи.

| Параметр | Значение |
|----------|----------|
| Единица данных | Кадр (Frame) |
| Устройства | Коммутатор (Switch), мост |
| Адресация | MAC-адрес |
| Протоколы | Ethernet, PPP, CDP, MPLS |

**MAC-адрес** — физический адрес сетевой карты:
```
00:16:52:00:1f:03
└──────┘ └───────┘
Произв.  Устройство
```
- 48 бит (6 байт)
- Уникален для каждого сетевого устройства
- Используется **внутри одной подсети**

**Структура Ethernet-кадра:**
```
┌──────────┬──────────────┬──────────────┬──────────┬──────────────┐
│ Преамбула│   MAC dst    │   MAC src    │  Тип     │    Данные    │  FCS │
│  8 байт  │   6 байт     │   6 байт     │  2 байт  │  46–1500 байт│ 4 байт│
└──────────┴──────────────┴──────────────┴──────────┴──────────────┘
```

**Подуровни канального уровня:**

| Подуровень | Название | Задача |
|------------|----------|--------|
| LLC | Logical Link Control | Взаимодействие с верхним уровнем |
| MAC | Media Access Control | Взаимодействие с физическим уровнем |

### Уровень 3 — Сетевой 🗺️

> [!note] Сетевой уровень
> Вводит **IP-адреса** и **маршрутизацию** — передачу данных между разными сетями.

| Параметр | Значение |
|----------|----------|
| Единица данных | Пакет (Packet) |
| Устройства | Маршрутизатор (Router) |
| Адресация | IP-адрес |
| Протоколы | IPv4, IPv6, ICMP |

**Структура IPv4 заголовка (ключевые поля):**

| Поле | Размер | Назначение |
|------|--------|------------|
| Версия | 4 бит | IPv4 или IPv6 |
| Тип обслуживания | 8 бит | Приоритет, задержка, надёжность |
| Общая длина | 16 бит | Размер всего пакета (макс. 65 536 байт) |
| TTL (Time To Live) | 8 бит | Число маршрутизаторов, через которые пройдёт пакет |
| Тип протокола | 8 бит | TCP или UDP (куда передать данные дальше) |
| Контрольная сумма | 16 бит | Пересчитывается на каждом роутере |
| IP отправителя | 32 бит | Адрес источника |
| IP получателя | 32 бит | Адрес назначения |

> [!warning] TTL — защита от вечного блуждания
> Каждый маршрутизатор уменьшает TTL на 1. Когда TTL = 0 — пакет уничтожается. Именно на этом работает **traceroute**.

**ICMP — протокол сообщений об ошибках:**
```
ping   → ICMP Echo Request  (тип 8, код 0)
         ICMP Echo Reply    (тип 0, код 0)

traceroute → посылает пакеты с TTL=1, 2, 3...
             получает ICMP "Time Exceeded" (тип 11, код 0)
             от каждого роутера
```

### Уровень 4 — Транспортный 🚚

> [!note] Транспортный уровень
> Отвечает за **доставку данных между приложениями** через порты. Два протокола: TCP и UDP.

#### TCP vs UDP

| Характеристика | TCP | UDP |
|----------------|-----|-----|
| Расшифровка | Transmission Control Protocol | User Datagram Protocol |
| Соединение | Устанавливается (handshake) | Нет |
| Гарантия доставки | ✅ Да | ❌ Нет |
| Порядок пакетов | ✅ Гарантирован | ❌ Не гарантирован |
| Скорость | Медленнее | Быстрее |
| Размер заголовка | 20+ байт | 8 байт |
| Применение | HTTP, HTTPS, Email | DNS, видеостриминг, игры |

**TCP — тройное рукопожатие (3-Way Handshake):**
```
Клиент          Сервер
  │── SYN ────────►│   "Хочу подключиться"
  │◄─── SYN-ACK ───│   "Принял, подтверждаю"
  │── ACK ────────►│   "Понял, начинаем"
  │                │
  │ ← данные ─────►│
```

**UDP — заголовок (всего 8 байт):**
```
┌──────────────┬──────────────┬────────┬───────────────┐
│  Порт отпр.  │  Порт получ. │ Длина  │ Контр. сумма  │
│   2 байта    │   2 байта    │ 2 байта│   2 байта     │
└──────────────┴──────────────┴────────┴───────────────┘
```

**Популярные порты:**

| Порт | Протокол | Назначение |
|------|----------|------------|
| 80 | HTTP | Веб (незашифрованный) |
| 443 | HTTPS | Веб (зашифрованный) |
| 53 | DNS (UDP) | Запросы к DNS |
| 67/68 | DHCP | Выдача IP-адресов |
| 22 | SSH | Безопасное удалённое управление |
| 21 | FTP | Передача файлов |

### Уровни 5, 6, 7 — Сеансовый, Представления, Прикладной

> [!note] Верхние уровни
> В модели **TCP/IP** эти три уровня объединяются в один **Прикладной уровень**. Здесь живут HTTP, DNS, DHCP.

| Уровень | Задача | Протоколы |
|---------|--------|-----------|
| 7 — Прикладной | Интерфейс пользователя | HTTP, FTP, DNS, DHCP, SMTP |
| 6 — Представления | Кодировка, сжатие, шифрование | TLS/SSL, JPEG, ASCII, UTF-8 |
| 5 — Сеансовый | Управление сессией (открыть/закрыть соединение) | NetBIOS, RPC |

## Модель TCP/IP (4 уровня)

> [!info] TCP/IP vs OSI
> TCP/IP — это **реальный** стек протоколов интернета. OSI — теоретическая модель. В жизни используется TCP/IP.

```
    OSI (7 уровней)          TCP/IP (4 уровня)
┌──────────────────┐      ┌──────────────────┐
│  7. Прикладной   │      │                  │
│  6. Представлен. │  ──► │   Прикладной     │  HTTP, DNS, DHCP
│  5. Сеансовый    │      │                  │
├──────────────────┤      ├──────────────────┤
│  4. Транспортный │  ──► │   Транспортный   │  TCP, UDP
├──────────────────┤      ├──────────────────┤
│  3. Сетевой      │  ──► │   Межсетевой     │  IP, ICMP
├──────────────────┤      ├──────────────────┤
│  2. Канальный    │      │                  │
│  1. Физический   │  ──► │   Канальный      │  Ethernet, Wi-Fi
└──────────────────┘      └──────────────────┘
```

> [!warning] Спорный момент
> Некоторые источники разделяют Канальный уровень TCP/IP на два: Канальный + Физический, получая 5-уровневую модель. Оба варианта встречаются на собеседованиях.

## Инкапсуляция данных

> [!example] Как данные "упаковываются" при отправке
> Каждый уровень добавляет свой **заголовок** к данным. Это называется инкапсуляция.

```
Прикладной:   [ ДАННЫЕ ]
Транспортный: [ TCP/UDP заголовок | ДАННЫЕ ]
Сетевой:      [ IP заголовок | TCP/UDP заголовок | ДАННЫЕ ]
Канальный:    [ MAC заголовок | IP заголовок | TCP/UDP заголовок | ДАННЫЕ | FCS ]
Физический:   101010111000101010011... (биты)
```
