#  HTTP и HTTPS

> **Теги:** #networks #http #конспект  

> [!abstract] Связи
> [[main]] | [[main Internet Networks]]

> [!abstract] Суть
> **HTTP (HyperText Transfer Protocol)** — протокол, по которому браузер получает страницы от сервера. Это фундамент всего веба. **HTTPS** = HTTP + шифрование TLS.

---

## Предыстория: гипертекст и URL

### Что такое гипертекст?

> [!note] Гипертекст
> Система страниц, связанных **ссылками**. Кажется очевидным сейчас, но в 1965 году это была революция.

- **1965** — Тед Нельсон ввёл термин «гипертекст»: *"материал взаимосвязанный таким образом, что его нельзя представить на бумаге"*
- **1989** — Тим Бернерс-Ли придумал Всемирную паутину (WWW) в CERN
- **1990** — первый веб-сервер — компьютер **NeXT Cube** (компания Стива Джобса)
- **1990** — первый браузер назван **"World Wide Web"**

### Анатомия URL

```
https://droider.ru/article/iphone-15/
  │       │          │
  │       │          └── Путь к ресурсу на сервере
  │       └─────────── Домен (хост)
  └─────────────────── Протокол
```

| Часть | Пример | Описание |
|-------|--------|----------|
| Протокол | `https://` | Способ передачи |
| Разделитель | `://` | Обязательный разделитель |
| Домен | `droider.ru` | Адрес сайта |
| Путь | `/article/iphone-15/` | Путь к странице/файлу |

> [!tip] Исторически
> Раньше пути заканчивались на `.html`, потому что страница — это буквально файл на сервере. Сейчас страницы генерируются динамически под каждый запрос.

## Архитектура клиент-сервер

```
┌──────────┐     HTTP запрос      ┌──────────┐
│          │──────────────────────►          │
│  Клиент  │                      │  Сервер  │
│ (браузер)│◄─────────────────────│          │
└──────────┘     HTTP ответ       └──────────┘
```

| Сторона | Что делает |
|---------|-----------|
| **Клиент** | Браузер — отправляет запросы, отображает страницы |
| **Сервер** | Компьютер со специальным ПО — обрабатывает запросы, отдаёт данные |

> [!info] Почему клиент-сервер, а не точка-точка?
> В старых сетях (FidoNet) компьютеры соединялись напрямую. Это не масштабируется. Сервер позволяет **миллиардам** клиентов обращаться одновременно. Если один сервер перегружен — нагрузка распределяется между несколькими.

## HTTP запрос

### Структура запроса

```
GET /weekly HTTP/1.1
Host: droider.ru
User-Agent: Mozilla/5.0
Accept: text/html
```

| Строка | Объяснение |
|--------|-----------|
| `GET /weekly HTTP/1.1` | Метод + путь + версия HTTP |
| `Host: droider.ru` | К какому сайту обращаемся (на одном IP могут быть разные сайты) |
| Остальные строки | Заголовки с доп. информацией |

### Методы HTTP

| Метод | Назначение | Пример |
|-------|-----------|--------|
| **GET** | Запросить страницу/данные | Загрузка сайта |
| **POST** | Отправить данные на сервер | Отправка комментария, формы |
| **HEAD** | Только заголовки без тела | Проверить, изменилась ли страница |
| PUT | Создать/заменить ресурс | Загрузка файла |
| DELETE | Удалить ресурс | — |
| PATCH | Частично изменить ресурс | — |

> [!tip] Используются чаще всего
> В 90% случаев: **GET** (получить) и **POST** (отправить). Остальные — редко.

## HTTP ответ

### Структура ответа

```
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 12345
Expires: Thu, 01 Jan 2025 00:00:00 GMT
Set-Cookie: session_id=abc123

<!DOCTYPE html>
<html>...
```

### Ключевые заголовки ответа

| Заголовок | Назначение |
|-----------|-----------|
| `Content-Type` | Тип данных: HTML-страница, файл, JSON и т.д. |
| `Expires` | До какой даты страница считается актуальной (кэш) |
| `Set-Cookie` | Установить cookie в браузер |
| `Content-Length` | Размер тела ответа |

### Коды ответа HTTP

```
1xx — Информационные
2xx — Успех
3xx — Перенаправление
4xx — Ошибка клиента
5xx — Ошибка сервера
```

| Код | Значение |
|-----|---------|
| `200 OK` | Всё хорошо |
| `301 Moved Permanently` | Перенаправление навсегда |
| `304 Not Modified` | Страница не изменилась (из кэша) |
| `400 Bad Request` | Неправильный запрос |
| `401 Unauthorized` | Нужна авторизация |
| `403 Forbidden` | Доступ запрещён |
| `404 Not Found` | Страница не найдена |
| `500 Internal Server Error` | Ошибка сервера |

## Кэширование и Cookie

### Кэш

> [!note] Кэш браузера
> Браузер сохраняет ответ сервера локально. При следующем одинаковом запросе — берёт из кэша, не тратит трафик.

```
Первый запрос:   Браузер → Сервер → Ответ + сохранить в кэш
Второй запрос:   Браузер → кэш (сервер не беспокоим)
```

- Заголовок `Expires` задаёт срок жизни кэша
- Когда срок истёк — страница помечается устаревшей, кэш очищается

### Cookie 🍪

> [!note] Cookie
> Небольшой файл, который сервер просит браузер хранить. Нужен для запоминания состояния пользователя.

**Зачем нужны cookie:**
- Сессия (вошёл ли пользователь в аккаунт)
- Корзина в интернет-магазине
- Пользовательские настройки
- Аналитика и трекинг

> [!danger] Уязвимость Cookie
> Cookie не шифруются и не привязаны к устройству. Если скопировать cookie с одного устройства на другое — можно **перехватить аккаунт**.
>
> **Реальный случай (2023):** Канал Linus Tech Tips (15 млн подписчиков) взломали именно так — сотрудник открыл вредоносный файл, который украл cookie и отправил злоумышленникам.

## HTTPS — безопасный HTTP

> [!danger] Проблема HTTP
> В HTTP **всё передаётся открытым текстом**. Любой посредник (провайдер, другой клиент в Wi-Fi) может прочитать и изменить данные. Такие атаки называются **Man-in-the-Middle (MITM)**.

```
Без HTTPS:
[Клиент] → пароль в открытом виде → [Хакер читает!] → [Сервер]

С HTTPS:
[Клиент] → 🔒 зашифровано → [Хакер видит мусор] → [Сервер]
```

### Что такое HTTPS?

| Параметр | Значение |
|----------|---------|
| Расшифровка | HyperText Transfer Protocol **Secure** |
| Появился | 1994 год (Netscape), стандарт — 2000 |
| Основа | HTTP + **TLS** (Transport Layer Security) |
| Порт | 443 |

### TLS — как работает шифрование

```
1. Клиент → Сервер: "Привет, хочу HTTPS соединение"
2. Сервер → Клиент: "Вот мой сертификат (публичный ключ)"
3. Клиент проверяет сертификат у доверенного центра (CA)
4. Клиент генерирует сессионный ключ, шифрует публичным ключом
5. Сервер расшифровывает своим приватным ключом
6. Оба знают сессионный ключ → данные шифруются симметрично
```

> [!warning] HTTPS не панацея
> MITM-атаки всё ещё возможны, если жертва **установит поддельный сертификат**. Но без этого — сделать это очень сложно.

## Версии HTTP

```
История развития:

1991 ── HTTP/0.9 ──── Только GET, только HTML
1996 ── HTTP/1.0 ──── Методы, коды, заголовки, любые данные
1997 ── HTTP/1.1 ──── Кэш, кодировки, постоянное соединение
              │
              └── Работал 20 лет без изменений!
              
2015 ── HTTP/2.0 ──── Мультиплексирование, сжатие заголовков
              │       Основа: протокол SPDY от Google
              │       Ускорение загрузки в ~2 раза
              │
2021 ── HTTP/3.0 ──── Основа: протокол QUIC от Google
                      Поддерживается всеми браузерами
```

| Версия | Год | Ключевые изменения |
|--------|-----|-------------------|
| **0.9** | 1991 | Только GET, только HTML |
| **1.0** | 1996 | Методы, коды ответа, заголовки, любые типы данных |
| **1.1** | 1997 | Кэширование, сжатие, постоянное соединение |
| **2.0** | 2015 | Мультиплексирование (параллельные запросы), сжатие заголовков |
| **3.0** | ~2021 | QUIC вместо TCP, ещё быстрее |

> [!tip] Почему не все переходят на HTTP/2 и 3?
> Переход требует изменений на всех уровнях — от кода сайта до серверов провайдера. При этом **новых функций** не появляется, только скорость. Большинству сайтов достаточно 1.1.
>
> YouTube уже использует **HTTP/3**. Большинство сайтов — до сих пор **1.1**.
