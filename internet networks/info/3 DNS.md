#  DNS — Domain Name System

> [!abstract] Суть одной строкой
> DNS — это **телефонная книга интернета**. Переводит человекочитаемые адреса (`youtube.com`) в машинные IP-адреса (`172.217.7.206`).

---

## Зачем нужен DNS?

```
Без DNS:  Пользователь вводит  →  172.217.7.206
С DNS:    Пользователь вводит  →  youtube.com  →  DNS →  172.217.7.206
```

> [!example] Аналогия
> Контакты в смартфоне. Ты ищешь «Иван Иванов», а не «+7 999 123-45-67». DNS делает то же самое: ты вводишь имя сайта, а DNS возвращает «номер» (IP).

---

## Иерархия DNS

```
                        ROOT ( . )
                       «Шао Кан» DNS
                      /     |      \
              ┌──────┘      │       └──────┐
             .com          .ru            .org
          (gTLD сервер)  (ccTLD сервер)   ...
              │              │
         google.com      merionet.ru
              │              │
         Авторитативный    Авторитативный
           сервер            сервер
              │              │
           IP-адрес       IP-адрес ✓
```

### Типы доменов верхнего уровня (TLD)

| Тип | Название | Примеры |
|-----|----------|---------|
| **gTLD** | Generic Top Level Domain — не привязаны к стране | `.com`, `.org`, `.edu`, `.ai` |
| **ccTLD** | Country Code TLD — привязаны к стране | `.ru`, `.us`, `.uk`, `.de` |

---

## Полный путь DNS-запроса

> [!example] Пример: вводим `wiki.merionet.ru`

```
Шаг 1: Проверяем кэш браузера/ОС
        ├── Нашли? → Готово, используем IP
        └── Не нашли? → Идём дальше

Шаг 2: Запрос к Resolver DNS (провайдер / 8.8.8.8 / 1.1.1.1)
        ├── Есть в кэше? → Отвечает нам
        └── Нет? → Идём к Root серверу

Шаг 3: Root сервер
        └── "Не знаю IP, но .ru — обратись к ccTLD серверу"

Шаг 4: ccTLD сервер (.ru)
        └── "Не знаю IP, но merionet.ru — обратись к их nameserver"

Шаг 5: Authoritative Nameserver (сервер merionet.ru)
        └── "wiki.merionet.ru → IP: 123.45.67.89" ✓

Шаг 6: Resolver кэширует ответ и передаёт нам IP
```

---

## Серверы в системе DNS

| Сервер | Роль | Аналогия |
|--------|------|---------|
| **Root сервер** | Вершина иерархии, знает где искать TLD серверы | Регистратура в поликлинике |
| **TLD сервер** | Отвечает за зону (.ru, .com, .org) | Отдел в книжном магазине |
| **Authoritative Nameserver** | Знает реальный IP конкретного домена | Сам стеллаж с нужной книгой |
| **Resolver** | Посредник, делает всю работу за нас | Библиотекарь |

> [!info] Где находится Resolver?
> - По умолчанию: у вашего **интернет-провайдера**
> - Можно сменить на публичные:
>   - `8.8.8.8` — Google DNS
>   - `1.1.1.1` — Cloudflare DNS

---

## Типы DNS-запросов

| Тип | Описание | Кто делает |
|-----|----------|-----------|
| **Recursive** (Рекурсивный) | "Дай мне IP wiki.merionet.ru" — сервер сам обходит иерархию | Клиент → Resolver |
| **Iterative** (Итеративный) | "Дай IP или скажи к кому идти дальше" | Resolver → Root/TLD |
| **Inverse** (Обратный) | "Какой домен у IP 123.45.67.89?" | Специальные случаи |

```
Клиент ──── Recursive ────► Resolver
                              │
                   Iterative  ├──► Root сервер
                              │
                   Iterative  ├──► TLD сервер
                              │
                   Iterative  └──► Authoritative NS
                                        │
            Клиент ◄──── IP ───────────┘
```

## Кэширование DNS

> [!note] TTL — Time To Live
> Каждая DNS-запись хранится ограниченное время — **TTL**. После истечения — запись удаляется, и при следующем запросе снова нужно идти по иерархии.

```
Цепочка кэширования:
Браузер кэш  →  ОС кэш  →  Resolver кэш  →  полный поиск
(быстро)        (быстро)    (средне)           (медленно)
```

**Команды для работы с DNS кэшем:**
```bash
# Windows
ipconfig /flushdns

# macOS
sudo dscacheutil -flushcache

# Linux
sudo systemd-resolve --flush-caches
```

## Структура доменного имени

```
wiki . merionet . ru
 │       │        │
 │       │        └── TLD (домен 1-го уровня)
 │       └──────────── Домен 2-го уровня (основной домен)
 └──────────────────── Субдомен (домен 3-го уровня)
```

> [!example] Сколько доменов в `wiki.merionet.ru`?
> **3 домена**: `ru` (1-й уровень) + `merionet` (2-й уровень) + `wiki` (3-й уровень / субдомен)

## DNS и протоколы

| Параметр | Значение |
|----------|---------|
| Протокол транспорта | **UDP** (порт 53) — для большинства запросов |
| TCP (порт 53) | Для больших ответов и zone transfer |
| Уровень OSI | Прикладной (7) |

> [!note] DNS через UDP
> Поскольку UDP не гарантирует доставку — если ответ не пришёл, запускается таймер и запрос отправляется снова.

---

## DNS в контексте полного запроса к сайту

```
Пользователь вводит youtube.com
        │
        ▼
   DNS-запрос → получаем IP (напр. 172.217.7.206)
        │
        ▼
   HTTP/HTTPS запрос к 172.217.7.206
        │
        ▼
   Получаем страницу
```

> [!tip] DNS отрабатывает ВСЕГДА первым
> Прежде чем браузер может отправить HTTP-запрос — он должен знать IP. Именно поэтому DNS работает до HTTP.
