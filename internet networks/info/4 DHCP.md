#  DHCP — Dynamic Host Configuration Protocol

> [!abstract] Суть одной строкой
> DHCP **автоматически выдаёт IP-адреса** устройствам в сети. Без него сисадмин должен вручную настраивать каждый компьютер.

---

## Зачем нужен DHCP?

| Без DHCP (статический IP) | С DHCP (динамический IP) |
|---------------------------|--------------------------|
| Сисадмин вручную вводит IP на каждом устройстве | DHCP сам раздаёт адреса автоматически |
| Легко ошибиться в настройках | Без ошибок, конфликтов нет |
| Терпимо для 2–3 компьютеров | Работает для сети любого размера |
| — | При подключении нового устройства — всё само |

---

## Архитектура DHCP

```
┌────────────────┐          ┌─────────────────┐
│  DHCP Клиент   │          │   DHCP Сервер   │
│ (ваш ПК/телефон)│◄────────►│ (роутер / выдел.│
│  IP нет ещё   │          │  машина)        │
└────────────────┘          └─────────────────┘
```

**DHCP-сервер хранит:**
- Пул (диапазон) IP-адресов для выдачи
- Маску подсети
- Шлюз по умолчанию (gateway)
- Адреса DNS-серверов
- Таблицу: IP ↔ MAC ↔ срок аренды

---

## Процесс получения IP (DORA)

> [!info] DORA — 4 шага выдачи адреса
> **D**iscover → **O**ffer → **R**equest → **A**cknowledge

```
Клиент                              Сервер (роутер)
  │                                     │
  │── DHCPDISCOVER ────────────────────►│
  │   src: 0.0.0.0                      │
  │   dst: 255.255.255.255 (broadcast)  │
  │   "Есть тут DHCP сервер?"           │
  │                                     │
  │◄─── DHCPOFFER ──────────────────────│
  │     "Вот тебе IP: 192.168.1.50"     │
  │     (по MAC-адресу клиента)         │
  │                                     │
  │── DHCPREQUEST ─────────────────────►│
  │   broadcast ко всем серверам!       │
  │   "Беру этот адрес"                 │
  │                                     │
  │◄─── DHCPACK ────────────────────────│
  │     "ОК, адрес твой"                │
  │     Сервер: IP→MAC в таблицу        │
  │             IP убран из пула        │
  │                                     │
```

### Почему DHCPDISCOVER — broadcast?

> [!note] У клиента ещё нет IP
> На этапе DISCOVER у устройства нет IP-адреса, поэтому:
> - **Источник**: `0.0.0.0` (нет адреса)
> - **Назначение**: `255.255.255.255` (всем в сети)
>
> Но у устройства есть **MAC-адрес** — этого достаточно для коммуникации на 2-м уровне OSI внутри подсети.

### Почему DHCPREQUEST — тоже broadcast?

> [!note] Несколько DHCP серверов
> В сети может быть несколько DHCP серверов. Рассылка в broadcast уведомляет **все** серверы о том, что клиент выбрал конкретный IP — остальные серверы вернут его в пул.

## Аренда IP-адреса

> [!warning] IP выдаётся временно!
> Пул адресов ограничен. Поэтому адреса выдаются **в аренду** на время сетевой активности.

```
Выдача → Аренда (lease time, обычно ~24 часа)
              │
              ├── Примерно раз в сутки: клиент шлёт DHCPREQUEST
              │   "Продли мне аренду"
              │
              ├── Сервер отвечает DHCPACK
              │   "Продлено"
              │
              └── Нет запроса? IP возвращается в пул
```

## Статическая резервация

> [!tip] Для серверов и принтеров
> Некоторые устройства должны иметь **постоянный** IP (принтеры, серверы, роутеры). Для них в DHCP настраивается **статическая резервация** — IP закрепляется за конкретным MAC-адресом навсегда.

```
MAC: AA:BB:CC:DD:EE:FF  →  IP: 192.168.1.10 (всегда)
MAC: 11:22:33:44:55:66  →  IP: из пула (каждый раз разный)
```

| Тип | Для кого | IP |
|-----|----------|-----|
| Динамический | Рабочие станции, телефоны, ноутбуки | Меняется |
| Статическая резервация | Принтеры, серверы, роутеры | Постоянный |

---

## Что ещё сообщает DHCP клиенту

Кроме IP-адреса, DHCP передаёт:

| Параметр | Пример | Зачем |
|----------|--------|-------|
| **IP-адрес** | `192.168.1.50` | Адрес устройства |
| **Маска подсети** | `255.255.255.0` | Определяет диапазон сети |
| **Шлюз** | `192.168.1.1` | Адрес роутера (выход в интернет) |
| **DNS серверы** | `8.8.8.8, 8.8.4.4` | Для разрешения доменных имён |
| **Lease time** | `86400 сек (24 ч)` | Время аренды IP |

## DHCP и уровни OSI

| Параметр | Значение |
|----------|---------|
| Уровень OSI | Прикладной (7) |
| Транспорт | UDP |
| Порт сервера | 67 |
| Порт клиента | 68 |

## Полная картина: что происходит при подключении к сети

```
Подключили кабель / подключились к Wi-Fi
             │
             ▼
       DHCP DORA
       (4 сообщения)
             │
             ▼
    Устройство получило:
    ✅ IP-адрес
    ✅ Маску подсети
    ✅ Шлюз (роутер)
    ✅ DNS-серверы
             │
             ▼
    Вводим youtube.com в браузере
             │
             ▼
       DNS-запрос → IP
             │
             ▼
       HTTP/HTTPS запрос
             │
             ▼
         Страница!
```
