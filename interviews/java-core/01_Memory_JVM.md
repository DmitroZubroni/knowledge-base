## 🔹 Области памяти JVM

| Область         | Назначение        | Что хранится                                                                        |
| --------------- | ----------------- | ----------------------------------------------------------------------------------- |
| **Heap Memory** | Куча              | Все новые объекты                                                                   |
| **Metaspace**   | Мета-пространство | Статическая информация, загруженные классы, статические переменные/методы, байт-код |
| **Code Cache**  | Кэш кода          | Скомпилированный нативный код (JIT компиляция)                                      |
| **Stack**       | Стек потока       | Вызовы методов, локальные переменные (у каждого потока свой стек)                   |

> [!note] Heap subdivisions
> Heap Memory может делиться на подобласти: String Pool, Integer Pool и другие в зависимости от версии Java и GC.

## 🔹 Примитивы vs Объекты

### Объекты
- Всегда создаются в **Heap**
- На стеке хранится только **ссылка** на объект
- Один объект может иметь внутри примитивы и ссылки на другие объекты в Heap

### Примитивы
- Если создаются как локальные переменные в потоке — хранятся на **стеке** потока
- Не попадают в Heap
- **Исключение:** примитив может храниться в Heap, если является частью объекта

```
Поток 1:
├── method() вызван
├── int x = 10        ← на стеке (примитив)
├── Object obj        ← на стеке ссылка
└── obj → Heap        ← сам объект в куче
```

> [!warning] Частый вопрос на собеседовании
> "Может ли примитив храниться в Heap?" — Да, если он является полем объекта.

## 🔹 String Pool (Пул строк)

**String Pool** — особая область в Heap Memory для кэширования строк.

### Создание строк

```java
String s1 = "Hello";        // литерал → в String Pool
String s2 = "Hello";        // литерал → ссылается на тот же объект в Pool
String s3 = new String("Hello");  // new → новый объект в Heap (не в Pool)
```

### intern()
```java
String s4 = new String("123").intern();  // копирует в String Pool
```

### StringBuilder vs StringBuffer

| Класс | Потокобезопасность | Когда использовать |
|-------|-------------------|-------------------|
| **StringBuilder** | Нет | Однопоточная среда (чаще всего) |
| **StringBuffer** | Да (синхронизированные методы) | Многопоточная среда |

> [!tip] Почему StringBuilder чаще?
- Обычно работаем со строками в одном потоке
- Нет оверхеда на синхронизацию

## 🔹 Immutability (Неизменяемость)

**Immutable объект** — объект, который нельзя изменить после создания.

### Зачем нужны immutable объекты

1. **Thread-safety** — если объект immutable, его нельзя изменить из разных потоков
2. **Ключи в HashMap** — hashCode ключа никогда не меняется

### Как создать immutable класс

1. Все поля **final**
2. Класс **final** (нельзя наследоваться)
3. Все внутренние поля тоже immutable
4. В конструкторе делать **копии** mutable объектов (например, List)
5. В геттерах возвращать **копии** внутренних mutable объектов
6. Закрыть сеттеры (или вообще не давать геттеров)

> [!warning] Почему класс должен быть final?
Если наследуемся и переопределим геттер, можем вернуть прямую ссылку на внутреннее состояние → нарушим иммутабельность.

## 🔹 Garbage Collection (Сборка мусора)

### Как GC определяет мусор

**GC Roots** — объекты, которые всегда доступны в программе:

| Тип GC Root | Примеры |
|-------------|---------|
| Статические переменные/методы | `static final Object obj` |
| Активные потоки | Локальные переменные на стеке потока |
| Синхронизация | Объекты с захваченным монитором (`synchronized`) |
| JNI | Объекты, используемые в нативном коде |

### Алгоритм работы GC

```
1. Маркировка (Mark)
   └─ GC проходит от GC Roots по ссылкам
   └─ Помечает все достижимые объекты

2. Удаление (Sweep)
   └─ Непомеченные объекты = мусор
   └─ GC удаляет их

3. Уплотнение (Compact)
   └─ Дефрагментация памяти
   └─ Объединяет свободные куски памяти
```

### GC алгоритмы

| Алгоритм | Структура Heap | Особенности | Default для |
|----------|----------------|-------------|-------------|
| **Serial GC** | Young/Old Generation | Одиночный поток, стоп-мир | Small apps |
| **Parallel GC** | Young/Old Generation | Многопоточный, стоп-мир | Java 8 default |
| **G1 GC** | Равные регионы | Garbage First — собирает регионы с максимумом мусора | Java 17 default |
| **ZGC** | Регионы | Для больших куч (до 16 ТБ), low latency (мс) | Java 21 default |

### Young vs Old Generation

```
Heap (Serial/Parallel GC):
├── Young Generation
│   ├── Eden          ← новые объекты
│   └── Survivor      ← пережили GC
└── Old Generation   ← долгоживущие объекты
```

- Объекты создаются в **Young Generation**
- Старые объекты перемещаются в **Old Generation**
- GC на Young Generation — часто
- Full GC (вся куча) — редко

## 🔹 Итог

> [!tip] Шпаргалка
> - **Heap** — объекты, **Stack** — примитивы и ссылки
> - **String Pool** — кэширование литералов, `intern()` для переноса
> - **StringBuilder** — однопоточный, **StringBuffer** — многопоточный
> - **Immutable** — final класс/поля, копии mutable объектов
> - **GC Roots** — статические, потоки, synchronized, JNI
> - **G1 GC** — Java 17 default, **ZGC** — Java 21 default (low latency)
> - **Young Generation** — новые объекты, **Old Generation** — долгоживущие

```
Области памяти:
Heap (объекты) | Metaspace (классы) | Code Cache (JIT) | Stack (переменные)

String:
"literal" → Pool | new String() → Heap | intern() → Pool

GC:
Mark-Sweep-Compact | G1 (Java 17) | ZGC (Java 21)
```
