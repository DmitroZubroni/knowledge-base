# 01 — Процессы и потоки

---

## 🔹 Зачем вообще многопоточность

Представь, что у тебя интернет-магазин. Пришёл запрос от пользователя — нужно сходить в базу данных, потом обработать данные, потом отдать ответ. Запрос в базу занимает 50 мс. Пока ждём ответ от базы — процессор просто стоит без дела.

Если всё делать в одном потоке — пока обрабатывается первый запрос, все остальные стоят в очереди. При 1000 запросах в секунду это катастрофа.

Многопоточность решает именно это:
- **Параллелизм** — несколько задач выполняются одновременно на разных ядрах CPU
- **Конкурентность** — несколько задач прогрессируют в перекрывающиеся промежутки времени (даже на одном ядре, пока одна задача ждёт I/O — другая работает)

```
Однопоточно:  [Запрос1----][Запрос2----][Запрос3----]
              ↑ долго, ждём друг друга

Многопоточно: [Запрос1----]
              [Запрос2----]
              [Запрос3----]
              ↑ всё параллельно, гораздо быстрее
```

## 🔹 Процесс vs Поток — в чём разница

**Процесс (Process)** — запущенная программа. Когда ты открываешь браузер — это процесс. Открываешь второй браузер — второй независимый процесс. Каждый процесс получает свою изолированную область памяти от операционной системы.

**Поток (Thread)** — единица выполнения внутри процесса. Один процесс может содержать множество потоков. Все потоки одного процесса **делят одну и ту же память**.

```
Операционная система
├── Процесс: браузер
│   ├── Память процесса (изолирована)
│   ├── Поток: рендеринг страницы
│   ├── Поток: загрузка файлов
│   └── Поток: JavaScript движок
│
└── Процесс: твоё Java приложение
    ├── Память процесса
    ├── Поток: main (стартует всегда)
    ├── Поток: GC (сборщик мусора)
    └── Поток: твои рабочие потоки
```

**Ключевые отличия:**

| | Процесс | Поток |
|-|---------|-------|
| Память | Изолированная, своя | Общая с другими потоками процесса |
| Создание | Дорого (копирование памяти) | Дёшево |
| Переключение | Дорого (сохранить весь контекст) | Дёшево |
| Общение | Сложно (IPC, сокеты, файлы) | Просто (общая память) |
| Сбой | Изолирован, не убивает другие | Может убить весь процесс |

## 🔹 Что происходит в JVM

Когда запускается Java-программа — JVM создаёт процесс, внутри которого сразу есть несколько потоков:

```
JVM Process
├── main thread          ← твой код начинает выполняться здесь
├── GC thread(s)         ← сборщик мусора работает параллельно
├── JIT compiler thread  ← компилирует байткод в машинный код
└── Finalizer thread     ← вызывает finalize() у объектов
```

Поток `main` — это точка входа. Когда `main()` завершается — JVM ждёт завершения всех **пользовательских потоков** (не-daemon), и только потом завершается сам.

## 🔹 Память: что общее, что личное

Это критически важно понять до изучения проблем многопоточности.

```
JVM Memory
│
├── HEAP (общая для всех потоков)
│   ├── Объекты (new Object(), new ArrayList(), ...)
│   ├── static поля классов
│   └── Здесь живут все объекты — любой поток может читать/писать
│
└── STACK (у каждого потока СВОЯ)
    ├── Локальные переменные методов (int i, String s, ...)
    ├── Параметры методов
    ├── Ссылки на объекты (но сами объекты — в heap)
    └── Фрейм вызова каждого метода
```

**Именно общий Heap — источник всех проблем многопоточности.** Когда два потока одновременно пишут в одно поле объекта в heap — возникает гонка данных.

```java
public class SharedData {
    int counter = 0;     // в HEAP — оба потока видят и могут менять
}

public void method() {
    int localVar = 5;    // в STACK — только этот поток видит
    SharedData data = new SharedData(); // ссылка в stack, объект в heap
}
```

## 🔹 Создание потоков — три способа

### Способ 1: extends Thread

```java
class MyThread extends Thread {
    @Override
    public void run() {
        // код, который выполнится в новом потоке
        System.out.println("Running in: " + Thread.currentThread().getName());
    }
}

MyThread t = new MyThread();
t.start(); // ← создаёт новый поток OS и запускает run()
```

> [!warning] `start()` vs `run()`
> `t.start()` — создаёт новый поток и запускает `run()` в нём. **Это то, что нужно.**
> `t.run()` — просто вызывает метод в текущем потоке. Никакого нового потока нет. Частая ошибка новичков.

### Способ 2: implements Runnable (предпочтительнее)

```java
class PrintTask implements Runnable {
    private final String message;

    PrintTask(String message) {
        this.message = message;
    }

    @Override
    public void run() {
        System.out.println(message);
    }
}

Thread t = new Thread(new PrintTask("Hello from thread!"));
t.start();

// Или через лямбду (Runnable — функциональный интерфейс)
Thread t2 = new Thread(() -> System.out.println("Lambda thread!"));
t2.start();
```

**Почему Runnable лучше Thread:**
- Java не поддерживает множественное наследование — если наследуешь Thread, больше ничего наследовать нельзя
- Разделение ответственности: `Runnable` — это **задача**, `Thread` — это **механизм выполнения**. Они должны быть отдельными.
- `Runnable` можно передать в `ExecutorService` — это правильный способ работы с потоками в реальных приложениях

### Способ 3: Callable (когда нужен результат)

```java
import java.util.concurrent.*;

Callable<Integer> task = () -> {
    Thread.sleep(1000);
    return 42; // возвращает результат, в отличие от Runnable
};

ExecutorService executor = Executors.newSingleThreadExecutor();
Future<Integer> future = executor.submit(task);
Integer result = future.get(); // 42
executor.shutdown();
```

## 🔹 Daemon потоки

Потоки делятся на два типа:

- **User thread (пользовательский)** — JVM ждёт его завершения перед выходом
- **Daemon thread** — фоновый поток. JVM не ждёт его и убивает когда завершаются все user threads

```java
Thread daemon = new Thread(() -> {
    while (true) {
        System.out.println("Daemon working...");
        Thread.sleep(100);
    }
});

daemon.setDaemon(true); // ВАЖНО: до start()!
daemon.start();

// Когда main() завершится — JVM не будет ждать daemon потока
// Он будет убит автоматически
```

> [!warning] `setDaemon()` нужно вызывать ДО `start()`
> После запуска потока изменить его тип нельзя — будет `IllegalThreadStateException`.

Примеры daemon потоков: GC, JIT компилятор, таймеры в некоторых фреймворках.

## 🔹 Итог

```
Процесс = изолированная программа со своей памятью
Поток   = единица выполнения внутри процесса

Потоки одного процесса:
  ДЕЛЯТ:  Heap (объекты, static поля) ← источник проблем
  НЕ ДЕЛЯТ: Stack (локальные переменные) ← у каждого свой

Создание потока:
  extends Thread     — редко (ограничивает наследование)
  implements Runnable — чаще (задача отдельно от механизма)
  Callable           — когда нужен результат

На практике — не создавай Thread напрямую.
Используй ExecutorService (см. [[08_ExecutorService]])

Daemon поток — фоновый, JVM его убивает при завершении.
setDaemon(true) — обязательно до start().
```
