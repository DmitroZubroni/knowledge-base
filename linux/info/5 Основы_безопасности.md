##  Теория: Принципы безопасности Linux

### Принцип минимальных привилегий

> Каждый процесс и пользователь должен иметь **только те права, которые необходимы** для выполнения задачи — и не более.

```
Плохо:  Запускать веб-сервер под root
Хорошо: Создать отдельного пользователя www-data для nginx
```

### Три уровня защиты

```
┌─────────────────────────────────────────┐
│  3. Мониторинг и аудит                  │
│     (логи, Lynis, auditd)               │
├─────────────────────────────────────────┤
│  2. Управление доступом                 │
│     (права файлов, sudo, PAM)           │
├─────────────────────────────────────────┤
│  1. Сетевая защита                      │
│     (брандмауэр, SSH, fail2ban)         │
└─────────────────────────────────────────┘
```

##  Разделение прав: пользователи и sudo

### Структура привилегий

| Тип | Описание |
|---|---|
| **root** | Суперпользователь, может всё |
| **sudo-пользователь** | Обычный пользователь с правом выполнять команды от root |
| **Обычный пользователь** | Доступ только к своим файлам |
| **Системный пользователь** | Для сервисов (nginx, postgres) |

```bash
# Добавить пользователя в группу sudo
sudo usermod -aG sudo username

# Проверить sudo-доступ
sudo -l                    # что может текущий пользователь
sudo -l -U username        # что может конкретный пользователь

# Запустить команду от другого пользователя
sudo -u www-data ls /var/www

# Переключиться на root
sudo su -
sudo -i
```

### Файл sudoers (`/etc/sudoers`)

```bash
sudo visudo    # ВСЕГДА редактировать только через visudo
```

```
# Синтаксис: кто  откуда=(от_чьего_имени) команды
root    ALL=(ALL:ALL) ALL
%sudo   ALL=(ALL:ALL) ALL
username ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx
```

## 🔒 Управление паролями

### Политика паролей (PAM)

```bash
sudo nano /etc/security/pwquality.conf
```

```
minlen = 12          # минимальная длина
minclass = 3         # классов символов (заглавные, цифры, спец.)
maxrepeat = 3        # максимальное повторение символов
dcredit = -1         # минимум 1 цифра
ucredit = -1         # минимум 1 заглавная
lcredit = -1         # минимум 1 строчная
ocredit = -1         # минимум 1 спецсимвол
```

### Управление паролями

```bash
passwd                    # изменить свой пароль
sudo passwd username      # изменить пароль пользователя
sudo passwd -l username   # заблокировать аккаунт
sudo passwd -u username   # разблокировать аккаунт
sudo chage -l username    # информация о сроке действия пароля
sudo chage -M 90 username # пароль действует 90 дней
sudo chage -E 2025-01-01 username  # аккаунт истекает в эту дату
```

##  UFW — Uncomplicated Firewall

### Теория

**UFW** — упрощённый интерфейс к iptables. Принцип работы:

```
Входящий трафик → Правила UFW → Разрешить / Отклонить
```

По умолчанию UFW: **блокирует входящее, разрешает исходящее**.

### Основные команды

```bash
sudo ufw status              # статус и правила
sudo ufw status verbose      # подробный статус
sudo ufw enable              # включить UFW
sudo ufw disable             # выключить UFW
sudo ufw reset               # сбросить все правила
```

### Управление правилами

```bash
# Разрешить
sudo ufw allow 22             # порт 22 (SSH)
sudo ufw allow ssh            # по имени сервиса
sudo ufw allow 80             # HTTP
sudo ufw allow 443            # HTTPS
sudo ufw allow 8080/tcp       # только TCP
sudo ufw allow from 192.168.1.0/24  # с подсети

# Запретить
sudo ufw deny 8080            # закрыть порт
sudo ufw deny from 192.168.1.50  # заблокировать IP

# Удалить правило
sudo ufw delete allow 80
sudo ufw delete deny 8080

# Ограничить (защита от brute-force)
sudo ufw limit ssh            # не более 6 попыток в 30 сек
```

### Приоритеты правил

```bash
sudo ufw insert 1 deny from 10.0.0.1  # вставить правило первым
```

##  iptables — продвинутый брандмауэр

### Теория

iptables — низкоуровневый инструмент фильтрации пакетов ядра Linux.

```
Пакет входит
     │
┌────▼──────────────────────────────┐
│             ТАБЛИЦЫ               │
│  filter  │  nat  │  mangle        │
│          │       │                │
│  INPUT   │PREROUTING│PREROUTING   │
│  OUTPUT  │POSTROUTING│OUTPUT      │
│  FORWARD │           │FORWARD     │
└───────────────────────────────────┘
     │
ACCEPT / DROP / REJECT
```

### Таблицы и цепочки

| Таблица | Цепочки | Назначение |
|---|---|---|
| `filter` | INPUT, OUTPUT, FORWARD | Фильтрация пакетов |
| `nat` | PREROUTING, POSTROUTING | Трансляция адресов |
| `mangle` | Все | Модификация пакетов |

### Цели (что делать с пакетом)

| Цель | Действие |
|---|---|
| `ACCEPT` | Пропустить пакет |
| `DROP` | Молча отбросить |
| `REJECT` | Отклонить с уведомлением |
| `LOG` | Записать в лог |

### Основные команды

```bash
sudo iptables -L              # список правил
sudo iptables -L -v           # подробно
sudo iptables -L --line-numbers  # с номерами строк
sudo iptables -L -n           # числовые адреса (быстрее)

# Добавить правила
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT   # разрешить SSH
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT   # разрешить HTTP
sudo iptables -A INPUT -p tcp --dport 8080 -j DROP   # запретить 8080

# Ограничить по IP
sudo iptables -A INPUT -p tcp --dport 22 -s 192.168.1.100 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -j DROP

# Удалить правило
sudo iptables -L --line-numbers           # найти номер
sudo iptables -D INPUT 3                  # удалить правило №3

# Очистить все правила
sudo iptables -F
```

### Сохранить правила iptables (Debian/Ubuntu)

```bash
sudo apt install iptables-persistent
sudo netfilter-persistent save
```

### UFW vs iptables

| Критерий | UFW | iptables |
|---|---|---|
| Сложность | ⭐ Простой | ⭐⭐⭐ Сложный |
| Гибкость | Базовая | Полная |
| Подходит для | Сервер / VPS | Роутер / Сложная инфра |
| Как работает | Генерирует iptables-правила | Напрямую |

> [!INFO] Связь UFW и iptables
> UFW на самом деле — это обёртка над iptables. Все команды `ufw` в конечном счёте создают правила iptables.

##  fail2ban — защита от brute-force

```bash
sudo apt install fail2ban
sudo systemctl enable fail2ban
sudo systemctl start fail2ban

# Просмотр статуса
sudo fail2ban-client status
sudo fail2ban-client status sshd   # статус тюрьмы SSH

# Разблокировать IP
sudo fail2ban-client set sshd unbanip 192.168.1.100
```

Конфигурация `/etc/fail2ban/jail.local`:

```ini
[sshd]
enabled = true
port = ssh
maxretry = 3
bantime = 3600    # 1 час
findtime = 600    # за 10 минут
```

##  Инструменты аудита безопасности

### Проверка открытых портов

```bash
sudo ss -tlnp          # что слушает
sudo netstat -tlnp     # альтернатива
nmap -sV localhost     # сканирование портов
```

### Lynis — аудит системы

```bash
sudo apt install lynis
sudo lynis audit system          # полный аудит
sudo lynis audit system --quick  # быстрый
```

### Проверка целостности файлов

```bash
# AIDE — Advanced Intrusion Detection Environment
sudo apt install aide
sudo aide --init             # создать базу
sudo aide --check            # сравнить с базой
```

##  Базовая настройка безопасности: чек-лист

```
✅ Создать обычного пользователя (не работать под root)
✅ Добавить пользователя в sudo
✅ Настроить политику паролей (/etc/security/pwquality.conf)
✅ Включить UFW, разрешить только нужные порты
✅ Отключить вход root по SSH (PermitRootLogin no)
✅ Настроить SSH-ключи, отключить пароль по SSH
✅ Установить fail2ban
✅ Регулярно проверять логи: journalctl -p err
✅ Обновлять систему: sudo apt update && sudo apt upgrade
```

### Практический пример

```bash
# 1. Создать пользователей
sudo adduser admin
sudo adduser user1
sudo usermod -aG sudo admin

# 2. Ограничить доступ к конфигу nginx
sudo chmod 600 /etc/nginx/nginx.conf

# 3. Настроить UFW
sudo apt install ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22
sudo ufw allow 80
sudo ufw allow 443
sudo ufw enable
sudo ufw status
```
