##  Теория: Веб-серверы

**Веб-сервер** — программа, которая принимает HTTP-запросы от браузеров и отдаёт контент (HTML, файлы, JSON).

### HTTP-запрос / ответ

```
Браузер                         Сервер
   │                               │
   │──── GET /index.html ──────────►│
   │                               │ nginx / apache
   │◄─── 200 OK + HTML ────────────│
   │                               │
```

### Сравнение веб-серверов

| | **Nginx** | **Apache** |
|---|---|---|
| Архитектура | Асинхронная, event-driven | Процессный (один поток = один запрос) |
| Потребление памяти | Низкое | Выше при нагрузке |
| Статический контент | ⭐⭐⭐ Отлично | ⭐⭐ Хорошо |
| Динамика (PHP и др.) | Через FastCGI/proxy | Модуль mod_php |
| Конфигурация | Единый nginx.conf | .htaccess (на уровне папок) |
| Применение | Высоконагруженные сайты, reverse proxy | Shared-хостинг, legacy |

## Nginx

### Установка и запуск

```bash
sudo apt update
sudo apt install nginx
sudo systemctl start nginx
sudo systemctl enable nginx    # автозапуск
sudo systemctl status nginx    # проверить статус
```

### Структура файлов Nginx

```
/etc/nginx/
├── nginx.conf           ← главный конфигурационный файл
├── sites-available/     ← доступные виртуальные хосты
│   └── default
├── sites-enabled/       ← включённые (символические ссылки)
│   └── default → ../sites-available/default
├── conf.d/              ← дополнительные конфиги
└── snippets/            ← переиспользуемые фрагменты
```

### Основной конфиг `/etc/nginx/nginx.conf`

```nginx
worker_processes auto;          # количество рабочих процессов

events {
    worker_connections 1024;    # соединений на воркер
}

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;

    sendfile        on;
    keepalive_timeout 65;

    include /etc/nginx/sites-enabled/*;
}
```

### Виртуальный хост (server block)

```nginx
server {
    listen 80;
    server_name example.com www.example.com;

    root /var/www/example.com;
    index index.html index.htm;

    location / {
        try_files $uri $uri/ =404;
    }

    # Логи
    access_log /var/log/nginx/example.access.log;
    error_log  /var/log/nginx/example.error.log;
}
```

### Команды Nginx

```bash
sudo nginx -t                  # проверить конфигурацию
sudo nginx -T                  # вывести весь конфиг
sudo systemctl reload nginx    # перезагрузить конфиг без рестарта
sudo systemctl restart nginx   # полный рестарт

# Создать виртуальный хост
sudo nano /etc/nginx/sites-available/mysite
sudo ln -s /etc/nginx/sites-available/mysite /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### Nginx как Reverse Proxy

```nginx
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

### HTTPS с Let's Encrypt

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d example.com -d www.example.com
sudo certbot renew --dry-run   # проверить автообновление
```

##  Apache

### Установка

```bash
sudo apt install apache2
sudo systemctl start apache2
sudo systemctl enable apache2
```

### Структура файлов Apache

```
/etc/apache2/
├── apache2.conf         ← главный конфиг
├── sites-available/     ← виртуальные хосты
├── sites-enabled/       ← включённые хосты
├── mods-available/      ← доступные модули
└── mods-enabled/        ← включённые модули
```

### Команды Apache

```bash
sudo a2ensite mysite.conf      # включить сайт
sudo a2dissite 000-default     # отключить сайт
sudo a2enmod rewrite           # включить модуль
sudo a2dismod rewrite          # отключить модуль
sudo apache2ctl configtest     # проверить конфиг
sudo systemctl reload apache2
```

##  Полезные утилиты Linux

### `curl` — работа с HTTP

```bash
curl https://example.com                    # GET-запрос
curl -I https://example.com                 # только заголовки
curl -o file.html https://example.com       # сохранить в файл
curl -L https://example.com                 # следовать редиректам
curl -X POST -d '{"key":"value"}' -H "Content-Type: application/json" https://api.example.com
curl -u user:pass https://example.com       # Basic Auth
curl -s https://example.com                 # без прогресса (silent)
curl -v https://example.com                 # подробный вывод (debug)
```

### `wget` — скачивание файлов

```bash
wget https://example.com/file.zip           # скачать файл
wget -c https://example.com/file.zip        # продолжить загрузку
wget -r https://example.com                 # рекурсивно скачать сайт
wget -q https://example.com/file            # тихо (quiet)
wget -P /tmp/ https://example.com/file      # в папку /tmp
```

##  Мониторинг и диагностика

### Использование ресурсов

```bash
free -h                        # оперативная память
vmstat 1 5                     # статистика VM (каждую секунду, 5 раз)
iostat -x 1                    # статистика I/O дисков
sar -u 1 10                    # нагрузка CPU (1 сек, 10 раз)
uptime                         # время работы + load average
```

### Анализ логов

```bash
# Nginx логи
sudo tail -f /var/log/nginx/access.log     # в реальном времени
sudo tail -f /var/log/nginx/error.log      # ошибки
sudo grep "404" /var/log/nginx/access.log  # только 404
sudo awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -20  # топ IP

# Системные логи
sudo journalctl -u nginx -n 50             # последние 50 строк nginx
sudo journalctl -p err --since "1 hour ago"  # ошибки за час
```

### `awk` и `sed` — обработка текста

```bash
# awk — обработка столбцов
awk '{print $1}' file.txt          # первый столбец
awk -F: '{print $1}' /etc/passwd   # разделитель :
awk '{sum += $1} END {print sum}' nums.txt  # сумма

# sed — замена текста
sed 's/old/new/g' file.txt         # заменить old на new
sed -i 's/old/new/g' file.txt      # в файле (in-place)
sed -n '5,10p' file.txt            # строки 5-10
sed '/pattern/d' file.txt          # удалить строки с pattern
```

### `tar` — архивирование

```bash
# Создать архив
tar -czf archive.tar.gz folder/        # gzip-сжатие
tar -cjf archive.tar.bz2 folder/       # bzip2-сжатие
tar -caf archive.tar.xz folder/        # xz-сжатие

# Распаковать
tar -xzf archive.tar.gz               # в текущую папку
tar -xzf archive.tar.gz -C /tmp/      # в /tmp/
tar -tzf archive.tar.gz               # просмотреть содержимое

# Флаги:
# c - создать, x - извлечь, t - просмотр
# z - gzip, j - bzip2, a - авто по расширению
# f - имя файла, v - verbose
```

## 🔐 SSL/TLS — HTTPS

### Самоподписанный сертификат (для тестов)

```bash
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout /etc/ssl/private/nginx-selfsigned.key \
    -out /etc/ssl/certs/nginx-selfsigned.crt
```

### Nginx с SSL

```nginx
server {
    listen 443 ssl;
    server_name example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    root /var/www/html;
}

# Редирект HTTP → HTTPS
server {
    listen 80;
    server_name example.com;
    return 301 https://$host$request_uri;
}
```

| `nc` (netcat) | "Швейцарский нож" для сети |

| `nmap` | Сканирование портов |
| `htop` | Мониторинг процессов |
| `jq` | Работа с JSON в командной строке |

```bash
# tmux — не потерять сессию при обрыве SSH
tmux new -s mysession      # создать сессию
tmux attach -t mysession   # подключиться к сессии
Ctrl+b d                   # отсоединиться (сессия остаётся)

# lsof — кто использует файл или порт
lsof /var/log/nginx/access.log   # кто читает файл
sudo lsof -i :80                 # что слушает порт 80
sudo lsof -i -P -n               # все сетевые соединения

# tcpdump — захват трафика
sudo tcpdump -i eth0             # весь трафик на eth0
sudo tcpdump -i eth0 port 80     # только HTTP
sudo tcpdump -i eth0 -w dump.pcap  # сохранить в файл
```

##  HTTP коды ответов

| Код | Категория | Значение |
|---|---|---|
| `200` | ✅ Успех | OK |
| `301` | ↩️ Редирект | Permanent Redirect |
| `302` | ↩️ Редирект | Temporary Redirect |
| `400` | ❌ Ошибка клиента | Bad Request |
| `401` | ❌ | Unauthorized |
| `403` | ❌ | Forbidden |
| `404` | ❌ | Not Found |
| `500` | 💥 Ошибка сервера | Internal Server Error |
| `502` | 💥 | Bad Gateway |
| `503` | 💥 | Service Unavailable |
