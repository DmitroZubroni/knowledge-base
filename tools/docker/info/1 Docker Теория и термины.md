##  Что такое Docker и зачем он нужен

**Docker** — это инструмент контейнеризации, который упрощает разработку, запуск и распространение программного обеспечения. По сути — обычная программа, которую устанавливают на компьютер/сервер.

### Проблемы, которые решает Docker

```
┌─────────────────────────────────────────────────────┐
│  Проблема 1: Конфликт зависимостей                  │
│  Приложение A требует lib v1.0                       │
│  Приложение B требует lib v2.0  ← конфликт!         │
│  Решение: каждый контейнер изолирует своё окружение │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  Проблема 2: "У меня работает, у тебя нет"          │
│  macOS → собрал → на Linux не запускается           │
│  Решение: один контейнер работает везде, где есть   │
│  Docker (Linux, macOS, Windows)                      │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  Проблема 3: Сложный деплой микросервисов           │
│  100+ сервисов, у каждого свои зависимости          │
│  Решение: каждый сервис в своём контейнере          │
└─────────────────────────────────────────────────────┘
```

##  Ключевые термины Docker

### Аналогия с печеньем

```
Чертёж формы        →  Dockerfile
Форма для выпечки   →  Docker Image
Готовое печенье     →  Docker Container
Изготовить форму    →  docker build (сборка образа)
Выпечка печенья     →  docker run (запуск контейнера)
```

---

###  Dockerfile

**Dockerfile** — текстовый файл с инструкциями по сборке образа. Разработчик пишет в нём что и как нужно сделать, а Docker выполняет эти инструкции.

```
Dockerfile → (docker build) → Image → (docker run) → Container
```

---

###  Docker Image (Образ)

**Image** — неизменяемый архив-шаблон, содержащий:
- Урезанную операционную систему (обычно Linux)
- Среду выполнения (JDK, Node.js, Python…)
- Код приложения
- Зависимости и конфиг

> [!NOTE] Image — это как класс в ООП
> Image — это шаблон. Container — экземпляр. Из одного image можно создать сколько угодно контейнеров.

Образы состоят из **слоёв (layers)**. Каждая инструкция в Dockerfile — это слой:

```
┌──────────────────────┐  ← COPY app.jar /app/   (слой 4)
├──────────────────────┤  ← RUN apt install curl  (слой 3)
├──────────────────────┤  ← WORKDIR /app          (слой 2)
├──────────────────────┤  ← FROM openjdk:17       (слой 1 — базовый)
└──────────────────────┘
```

Слои **кэшируются** — при повторной сборке Docker пересобирает только изменённые слои и всё, что после них.

---

###  Docker Container (Контейнер)

**Container** — запущенный экземпляр Image. Это изолированный процесс с:
- Собственной файловой системой
- Собственным сетевым пространством
- Собственными переменными окружения

> [!INFO] Контейнер ≠ виртуальная машина
> Контейнер — это обычный процесс на хостовой ОС, но изолированный с помощью механизмов ядра Linux (namespaces + cgroups).

---

###  Docker Hub (Registry)

**Docker Hub** — облачное хранилище образов (как GitHub, только для Docker образов).

```
Разработчик       DockerHub        Другой сервер
     │                │                  │
     ├─── push ──────►│                  │
     │   (загрузить)  │◄── pull ─────────┤
     │                │  (скачать)       │
```

**Что есть на Docker Hub:**
- Официальные образы: `ubuntu`, `nginx`, `postgres`, `redis`, `node`, `python`…
- Образы сообщества
- Ваши приватные образы

---

###  Docker Engine

**Docker Engine** — сам механизм Docker. Состоит из:

```
┌──────────────────────────────────────┐
│          Docker Client (CLI)         │  ← вы вводите команды
│        docker run / build / ps       │
└──────────────────┬───────────────────┘
                   │ REST API
┌──────────────────▼───────────────────┐
│        Docker Daemon (dockerd)       │  ← сервер, всем управляет
│   создаёт контейнеры, образы, тома   │
└──────────────────────────────────────┘
```

---

###  Docker Volume (Том)

**Volume** — механизм хранения данных вне контейнера. Нужен потому, что данные внутри контейнера исчезают при его удалении.

```
┌─────────────────┐        ┌──────────────────┐
│   Контейнер     │        │    Docker Volume  │
│   PostgreSQL    │◄──────►│   /var/lib/pgsql  │
│                 │        │  (данные на диске)│
└─────────────────┘        └──────────────────┘
```

---

###  Docker Network (Сеть)

**Network** — виртуальная сеть для взаимодействия контейнеров между собой.

```
┌─────────────┐   docker_network   ┌─────────────┐
│  app:8080   │◄──────────────────►│  postgres   │
│ (бэкенд)    │                    │  :5432      │
└─────────────┘                    └─────────────┘
       │
  опубликован
  на порт 80
       │
  ► браузер
```

##  Жизненный цикл контейнера

```
           docker run
Образ ─────────────────► Created
                              │
                          docker start
                              │
                              ▼
                           Running ◄────────────────┐
                              │                     │
                         docker stop           docker restart
                              │                     │
                              ▼                     │
                           Stopped ─────────────────┘
                              │
                         docker rm
                              │
                              ▼
                           Deleted (удалён навсегда)
```

| Состояние | Описание |
|---|---|
| `created` | Создан, но не запускался |
| `running` | Работает прямо сейчас |
| `paused` | Приостановлен (заморожен) |
| `stopped/exited` | Остановлен |
| `dead` | Завершился с ошибкой |

##  Ключевые принципы

> [!TIP] Один контейнер = одна задача
> Не запускайте базу данных и веб-сервер в одном контейнере. Разделяйте ответственность.

> [!TIP] Контейнеры — эфемерны
> Не храните важные данные внутри контейнера. Используйте Volumes.

> [!TIP] Image — неизменяем
> Нельзя изменить запущенный Image. Любые изменения — это новый Image.
