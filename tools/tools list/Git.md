## Теория: основные термины

|Термин|Описание|
|---|---|
|**Репозиторий**|Хранилище (папка `.git`)|
|**Коммит**|Снимок изменений + метаданные (ID, автор, дата, комментарий)|
|**Ветка**|Подвижный указатель на коммит|
|**Слияние (merge)**|Перенос изменений из одной ветки в другую|
|**Конфликт**|Ситуация, когда Git не может автоматически объединить изменения|
|**Pull**|Забрать изменения с удалённого репозитория|
|**Push**|Отправить изменения в удалённый репозиторий|
|**.gitignore**|Файл с шаблонами игнорируемых файлов/папок|

## Коммит – структура

Коммиты образуют **односвязный список** (каждый знает предыдущий).

```text
[commit #1] ← [commit #2] ← [commit #3] (HEAD -> master)
```

**Метаданные коммита**:

- Уникальный **хеш** (ID)
    
- **Автор** и **дата**
    
- **Комментарий** (message)
    

---

## Ветка – указатель на коммит

```text
master → [C1] ← [C2] ← [C3]
                         ↑
                    feature → [C4]
```

- Создание новой ветки – новый **указатель** на существующий коммит.
    
- Новые коммиты двигают указатель ветки вперёд.

## Работа с локальным репозиторием

### 1. Инициализация


```bash
git init
```

Появится папка `.git` – удалять нельзя ⚠️

### 2. Статус

```bash
git status
```

### 3. Добавление в **staged** (подготовка)

|Команда|Действие|
|---|---|
|`git add -A`|Добавить всё|
|`git add .`|Добавить из текущей папки и подпапок|
|`git add <файл>`|Добавить конкретный файл|
|`git add *.txt`|Добавить все `.txt` файлы|

### 4. Коммит

```bash
git commit -m "осмысленное сообщение"
```

### 5. Просмотр истории

```bash
git log          # полная история
git log --oneline# сокращённо
```

### 6. Сравнение изменений

```bash
git diff         # что изменилось, но ещё не в staged
```

##  .gitignore

Создайте файл `.gitignore` в корне проекта. Каждая строка – шаблон.

|Пример|Что игнорирует|
|---|---|
|`*.class`|все `.class` файлы|
|`target/`|папку `target` и всё внутри|
|`*.iml`|файлы IntelliJ IDEA|
|`.idea/`|папку конфигурации IDE|

```bash
git add .gitignore
git commit -m "add gitignore"
```

##  Работа с ветками

### Посмотреть все ветки

```bash
git branch -a
```

### Создать ветку

```bash
git branc -M main
```

# на основе текущей
git checkout -b new-branch
# на основе конкретного коммита (хеш можно взять из git log)
git checkout -b dev 6c44e53

### Переключиться на ветку

```bash
git checkout master
```

### Слияние ветки (merge)

```bash
git checkout master
git merge feature-branch
```

### Удалить ветку

```bash
git branch -D feature-branch
```

##  Разрешение конфликтов

**Конфликт** возникает, если в одной и той же строке файла изменения в двух ветках различны.



**Действия**:

1. Открыть конфликтующий файл, вручную оставить нужный код (убрать `<<<`, `===`, `>>>`).
    
2. `git add <файл>`
    
3. `git commit` (без `-m` – Git откроет редактор с предложенным сообщением о слиянии)
    

> [!warning] После разрешения конфликта всегда делайте **коммит**!

##  Удалённые репозитории

Популярные хостинги: **GitHub**, **GitLab**, **Bitbucket**.

### Клонирование

```bash
git clone https://github.com/user/repo.git
```

### Забрать изменения

```bash
git pull          # git fetch + git merge
```

### Отправить изменения

```bash
git push
```


**Типичный цикл работы с удалённым репозиторием**:

1. `git pull` – получить актуальную версию
    
2. Внести изменения, `git add`, `git commit`
    
3. `git push` – отправить свой коммит

## 📋 Шпаргалка основных команд

|Команда|Действие|
|---|---|
|`git init`|Создать локальный репозиторий|
|`git status`|Показать состояние файлов|
|`git add .`|Добавить все изменения в staged|
|`git commit -m "msg"`|Закоммитить подготовленные изменения|
|`git log`|История коммитов|
|`git diff`|Разница между изменениями|
|`git branch -a`|Список веток|
|`git checkout -b branch`|Создать и переключиться на новую ветку|
|`git merge branch`|Слить ветку в текущую|
|`git clone url`|Склонировать удалённый репозиторий|
|`git pull`|Обновить локальную копию из удалённого|
|`git push`|Отправить локальные коммиты в удалённый репозиторий|
